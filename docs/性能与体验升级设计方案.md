# keepBoard 性能与体验升级设计方案

## 1. 目标

本方案面向 keepBoard 当前的 Electron + React + TypeScript + WebGL2 架构，目标不是推倒重写，而是在保留现有产品气质的基础上，完成两条升级线：

- 性能线：把每帧计算压力最大的字符 3D 形体生成逻辑下沉，降低大尺寸窗口和复杂形状下的 CPU 占用。
- 体验线：让桌面宠物的反馈更丝滑、更高级、更有趣，同时让统计面板从“工具窗口”升级为有品牌感的数据体验。

## 2. 现状判断

### 2.1 已经做得好的部分

- 字符绘制已经默认走 WebGL2 图集 + instancing，一帧只需一次 draw call，GPU 渲染路径方向正确。
- 全局输入监听使用 `uiohook-napi`，已有原生能力，不需要重新造底层 hook。
- 统计写盘已做 2 秒 debounce，日级数据结构简单，当前不构成性能瓶颈。
- 动画循环会在速度衰减至 0 后停止，水母待机也降到约 12 FPS，常驻桌面应用的功耗意识已经具备。

### 2.2 当前主要瓶颈

真正需要优化的是 `PetCanvas.tsx` 中每帧生成字符实例的 CPU 计算：

- `sphere`、`cube`、`saturn` 按字符网格逐 cell 扫描，窗口越大，循环量越高。
- `donut`、`mobius`、`jellyfish` 按参数曲面采样，包含大量三角函数、投影、深度比较和光照计算。
- WebGL 只负责最后绘制，CPU 仍然在 JS 中生成 `GlyphInstance[]`。
- 复杂形状在 480px/640px、频繁输入或长期动态效果下更容易吃 CPU。

结论：C++/WASM 最值得接管的是“形体求值器”，不是 React UI、菜单、设置或日周统计。

## 3. 性能重构方案

### 3.1 推荐方向

优先做一个独立的 native/wasm shape evaluator：

```text
输入：
  shape、cols、rows、angleA、angleB、colorShift、palette、charset、shapeOptions

输出：
  packed glyph buffer
  [x, y, glyphIndex, colorIndex] * count
```

前端仍保留：

- WebGLGlyphRenderer
- canvas fallback
- 输入事件监听和动画速度控制
- 菜单设置与形状切换

下沉模块负责：

- 形体采样或屏幕空间 raycast
- z-buffer
- 光照和字符亮度映射
- 颜色索引计算
- 输出 compact typed array

### 3.2 技术路线选择

#### 方案 A：C++ N-API

优点：

- 与 Electron/Node 结合自然。
- 可以复用 Node 原生 addon 分发体系。
- 性能最好，适合未来更多复杂形状。

缺点：

- Windows/Linux/macOS 打包复杂度上升。
- electron-builder 需要处理 native addon unpack/rebuild。
- 本地编译链和 CI 需要更认真维护。

适合：追求桌面端极致性能，且主要面向 Electron。

#### 方案 B：C++ 编译到 WASM

优点：

- 分发简单，前端直接加载 `.wasm`。
- 跨平台压力小，不受 Electron ABI 影响。
- 迁移风险更低，失败时容易回退到 TS。

缺点：

- 与 JS 之间仍有 buffer 传递成本。
- 调试体验弱于纯 TS。
- SIMD/threads 需要额外兼容性判断。

适合：作为第一阶段原型，验证性能收益。

#### 方案 C：Rust/WASM

优点：

- 类型和内存安全更好。
- 适合以后如果迁移到 Tauri。

缺点：

- 当前项目已有 TypeScript/Electron/C++ 讨论背景，Rust 会引入另一套工具链。

适合：如果未来明确要往 Tauri/Rust 方向演进。

### 3.3 推荐结论

先做 WASM evaluator 原型，再决定是否升级到 C++ N-API。

理由：

- 当前首要任务是验证“下沉 shape evaluator 是否显著降 CPU”。
- WASM 对 Electron 打包侵入更小。
- 可以先迁移一个复杂但边界清晰的形状，例如 `sphere` 或 `saturn`。
- 如果收益明显，再迁移更多形状；如果收益一般，保留 TS 方案即可。

### 3.4 模块设计

新增模块建议：

```text
src/lib/shapeEngine/
  index.ts                 # TS facade，统一选择 wasm/native/ts fallback
  types.ts                 # ShapeFrameInput / ShapeFrameOutput
  fallback.ts              # 当前 TS evaluator 的兼容入口
  wasmLoader.ts            # WASM 加载与能力检测

native/shape-engine/
  shape_engine.cpp         # C++/WASM 核心
  shapes/
    sphere.cpp
    saturn.cpp
    cube.cpp
  include/
    shape_engine.h
```

前端调用方式：

```ts
const frame = shapeEngine.renderFrame({
  shape,
  cols,
  rows,
  angleA,
  angleB,
  colorShift,
  timeMs
})

gpu.drawPacked(frame.buffer, frame.count)
```

`WebGLGlyphRenderer` 后续可增加 `drawPacked()`，避免从 packed buffer 再转成对象数组。

### 3.5 分阶段迁移

#### P0：基准采集

交付：

- 开发模式增加渲染诊断 overlay 或 console metrics。
- 记录每帧：
  - evaluator 耗时
  - WebGL draw 耗时
  - charCount
  - cols/rows
  - shape
  - FPS

验收：

- 能对 220/320/480/640 四档窗口尺寸输出稳定数据。
- 能比较 `donut/sphere/saturn/jellyfish` 的平均耗时和 P95 耗时。

#### P1：迁移 sphere

原因：

- `sphere` 是规则的屏幕空间求交，输入输出边界清楚。
- 当前按 `COLS * ROWS` 扫描，适合作为性能验证样本。

交付：

- WASM sphere evaluator。
- TS fallback 保持不变。
- `renderer=ts|wasm` 开发参数切换。

验收：

- 输出视觉与现有 sphere 基本一致。
- 480/640 下 evaluator 平均耗时明显降低。
- 切换 shape、resize、theme、charset 不出现崩溃。

#### P2：迁移 saturn / cube

原因：

- 二者同样有 raycast/逐 cell 特征。
- `saturn` 计算更重，收益会更明显。

交付：

- `saturn` 和 `cube` evaluator。
- 公共数学工具抽到 native 层。
- z-buffer、palette index 逻辑统一。

验收：

- 视觉遮挡关系正确。
- 土星星环前后遮挡与当前实现一致。
- 大尺寸窗口输入连续触发时 CPU 占用下降。

#### P3：优化数据传输和 WebGL 提交

交付：

- `GlyphInstance[]` 改为 typed array packed buffer。
- `WebGLGlyphRenderer.drawPacked()` 直接上传 Float32Array 或混合 typed array。
- 颜色字符串解析从每帧路径中移除，改为 palette uniform/texture 或 color index。

验收：

- JS 对象分配显著减少。
- 长时间运行 GC 抖动下降。
- Canvas fallback 仍可用。

## 4. 体验升级方案

### 4.1 设计方向

关键词：

- 丝滑：输入反馈不突兀，动画有惯性、缓动、余韵。
- 高级：面板减少厚重像素边框堆叠，用克制层次承载数据。
- 有趣：宠物不只是旋转物体，而是会对输入强度和用户状态作出反应。

### 4.2 宠物动画升级

#### 输入反馈分层

当前输入主要触发旋转 kick。建议拆成三层反馈：

```text
键盘：
  旋转加速 + 亮度脉冲 + 轻微 scale squash

鼠标点击：
  局部点击涟漪 + 瞬时偏航 + 短促高光

滚轮：
  色带流动加速 + 形体纵向波纹
```

新增状态：

- `calm`：普通待机，低功耗。
- `focused`：持续输入时，色彩更亮，旋转更稳定。
- `combo`：短时间高频输入，出现连击数字或环形粒子。
- `idle`：长时间无输入，亮度下降，动作变慢。
- `milestone`：达到每日目标或整百/整千键击时触发庆祝。

#### 动效原则

- 使用缓动曲线替代线性突变。
- 所有反馈应有 150-600ms 的尾韵。
- 复杂粒子只在 milestone/combo 出现，平时保持轻量。
- 视觉变化优先使用已有 WebGL 字符图集，不引入大图资源。

### 4.3 统计面板升级

当前面板偏复古工具窗口，可以升级为“像素数据卡片”：

- 今日面板首屏突出 3 个主指标：键击、点击、屏时。
- 按键分类从纯列表改为迷你横向条形图。
- 峰值 APM 增加小型 sparkline 或节奏条。
- 每周面板柱状图增加进入动画和 hover 高亮。
- 导出反馈用 toast/状态条，不把长路径挤进主布局。

视觉建议：

- 背景保持深色，但减少纯黑重边框。
- 使用 1px/2px 像素线做结构，不到处使用厚重内阴影。
- 主数字使用更大字号，次级信息降低饱和度。
- 黄色只用于关键数字和达成状态，避免全局抢眼。
- 红橙色主要给 warning/combo/peak，不作为普通填充色。

### 4.4 菜单与设置体验

现有右键菜单功能多，但层级会越来越深。建议：

- 保留右键菜单作为快速入口。
- 增加一个独立“外观工作台”窗口：
  - 形状预览
  - 配色预览
  - 字符集预览
  - glow/randomSpin/opacity 控制
  - 自定义 look 编辑和即时刷新

这样可以让高级配置更可玩，同时不污染桌面宠物主窗口。

## 5. 产品化升级建议

### 5.1 成就与目标

低成本但很有趣的功能：

- 每日 1000/3000/5000 键击里程碑。
- 连续活跃 25 分钟触发专注徽章。
- 一周 5 天有记录触发周活跃徽章。
- 新形状/配色可以作为成就奖励解锁。

数据结构可先放在现有 JSON store 中：

```ts
interface AchievementState {
  unlocked: Record<string, string>
  dailyGoal: number
  lastCelebrated: Record<string, string>
}
```

### 5.2 状态驱动外观

让统计数据影响宠物外观：

- 今日键击越多，色带流动越强。
- 当前 APM 越高，glow 越明显。
- 空闲越久，亮度越低。
- 达成目标后当天出现特殊 halo。

这会让 keepBoard 从“记录工具”变成“数据驱动的陪伴物”。

## 6. 风险与控制

### 6.1 Native/WASM 风险

风险：

- 打包链复杂。
- 调试成本上升。
- 输出与 TS 视觉不一致。
- buffer 协议设计不当反而增加 JS/WASM 传输成本。

控制：

- 先只迁移一个形状。
- 保留 TS fallback。
- 增加开发参数强制切换 evaluator。
- 做截图或像素级差异检查。
- 不在第一阶段改 WebGLRenderer 的公共接口太多。

### 6.2 体验升级风险

风险：

- 动效过多导致桌面常驻变吵。
- “高级感”稀释像素风辨识度。
- 面板升级引入布局拥挤。

控制：

- 所有高强度动效只在输入或里程碑短暂出现。
- 默认状态保持安静。
- 保留像素字体、字符形体和像素线条作为品牌核心。
- 增加“低调模式”或沿用现有 glow/opacity 开关。

## 7. 推荐实施路线

### 第一阶段：测量与验证

- 增加渲染耗时指标。
- 做 `sphere` WASM evaluator 原型。
- 对比 TS/WASM 在 320/480/640 下的耗时。

### 第二阶段：感知体验升级

- 输入事件拆分为 keyboard/click/wheel 三类视觉 impulse。
- 统计面板改版：主指标卡、分类条形图、周图动画。
- 增加 milestone 庆祝效果。

### 第三阶段：性能深化

- 迁移 `saturn` 和 `cube`。
- packed buffer 直连 WebGL。
- 减少每帧对象分配和颜色字符串解析。

### 第四阶段：高级玩法

- 外观工作台。
- 成就和每日目标。
- 数据驱动外观状态。

## 8. 验收指标

性能指标：

- 640px 下复杂形状 evaluator 平均耗时下降 30% 以上。
- 输入连续触发 60 秒无明显卡顿。
- 空闲状态 CPU 保持低占用。
- 长时间运行无明显 GC 抖动。

体验指标：

- 键盘、鼠标、滚轮反馈有明显差异。
- 统计面板首屏 3 秒内能读懂今日状态。
- 默认视觉更克制，但 milestone/combo 有惊喜。
- 原有形状、配色、字符集、glow、随机转向功能全部保留。

## 9. 优先级清单

| 优先级 | 任务 | 价值 | 风险 |
|---|---|---|---|
| P0 | 渲染耗时 metrics | 找准瓶颈 | 低 |
| P0 | sphere WASM 原型 | 验证下沉收益 | 中 |
| P1 | 输入 impulse 分层 | 立刻提升手感 | 低 |
| P1 | 统计面板视觉升级 | 提升高级感 | 中 |
| P1 | milestone 庆祝 | 提升趣味性 | 低 |
| P2 | saturn/cube 下沉 | 降低复杂形状 CPU | 中 |
| P2 | packed buffer draw | 降低分配和传输成本 | 中 |
| P3 | 外观工作台 | 提升可玩性 | 中 |
| P3 | 成就/目标系统 | 提升留存 | 中 |

## 10. 最小可行版本

如果只做一个小而漂亮的版本，建议范围如下：

1. 增加渲染 metrics。
2. 增加 keyboard/click/wheel 三类 impulse。
3. 改版统计面板主视觉。
4. 增加每日 1000 键击 milestone。
5. 做 `sphere` WASM 原型但不默认启用。

这个版本既能看到体验变化，也能验证 C++/WASM 方向是否值得继续投入。
